    Ontology-based natural-language querying over knowledge graphs

    Hermes

    Ask a question in English; Hermes writes SPARQL from the slice of the ontology the question needs, repairs it, plans it as relational algebra with the graph's statistics, and runs it, pricing every model call and graph query before it spends it.

    How it works

    The ontology is the schema and the knowledge graph is the data. A question goes through seven stages:

    1. Refinethe ontology slice the question needs
    2. Examplessynthetic pairs from the graph
    3. Generateone model call writes SPARQL
    4. Repairprefixes, terms, types, probes
    5. Planrelational algebra, rewritten
    6. Pricechecked against the budget
    7. Executethe plan runs on the graph

    One model call writes the query; everything after it is checked before it costs anything, and the model is asked again only when a check fails and the budget allows. See Pipeline.

    Quick start

    git clone https://github.com/lamng3/hermes.git && cd hermes
pip install -e ".[dev]"
hermes data fetch ck26                          # the Text2SPARQL corporate graph and benchmark
hermes ask --graph corporate "Which department does Ms. Brant belong to?"
    from hermes import Budget, Hermes, KnowledgeGraph

kg = KnowledgeGraph.from_files("ontology.ttl", "data.ttl", schema=["ontology.ttl"])
answer = Hermes(kg, budget=Budget(llm_calls=3)).ask("Which cities hosted the Winter Olympics?")
print(answer.sparql, answer.rows, answer.spend.total)

    The model is a local one through Ollama by default, or any OpenAI-compatible API; see Python and CLI.

    What is measured

    On the gold queries of the Text2SPARQL 2026 benchmarks, every plan that ran returned the engine's answers, and the optimizer cut the work; Planner has the details. The pipeline's accuracy and cost are on Evaluation.
