    Pipeline

    A question goes through seven stages; each reports to observers as it starts and ends, and each prices what it is about to spend.

    The ontology catalog

    Everything the model may need to know about the graph. From the ontology: classes and properties with labels, comments, declared domains and ranges. From the data: how often each term is used, which properties the instances of each class use, which classes a property's objects belong to, whether a property holds literals or entities, the values of properties with few distinct values (currencies, countries), and the members of classes with at most 100 instances (departments, product categories). Built once per graph; 0.1 s for the corporate graph. Source: catalog.py.

    The ontology refiner

    Hermes keeps the classes, properties and values that rank highest for the question, adds the properties the chosen classes' instances use and the classes at both ends of the chosen properties, and links the entities the question names: exact labels, members of small classes the question names, and capitalized mentions ("Ms. Brant" finds "Karen Brant"). Ranking is pluggable: BM25 by default, or embeddings from any OpenAI-compatible or Ollama endpoint (retrieval.py).

    Properties (subject → object):
- pv:memberOf "member of": Agent, Employee, Manager → Department
Values that occur in the graph:
- pv:addressCountry "France"
Entities named in the question:
- prodi:prod-cat-Compensator "Compensator" (Product Category)

    Few-shot examples

    Built from the graph, never from benchmark questions (synthetic.py): template queries over the catalog (an entity's attribute, a relation either way, instances with a listed value, a count, a superlative, two hops), filled with sampled entities and kept when they return 1 to 50 rows. The model writes the question each query answers from its terms' labels, and the pair is kept only if the pipeline, without examples, answers that question with the same answers (F1 ≥ 0.7). hermes fewshot build --graph corporate writes data/fewshot/corporate.jsonl; the two closest examples go in each prompt.

    Generate

    One call. The prompt is built by a builder (prompt.py) from instructions, prefixes, the ontology slice, the examples and the question.

    The query refiner

    Cheapest first, each change recorded (repair.py):

    1. declare prefixes the query uses but forgot; move ORDER BY and LIMIT out of WHERE;
    2. replace an unknown property or class by the closest known name;
    3. replace an entity IRI the graph does not mention by the entity whose label matches it;
    4. check types: a class used as a property, a literal where a property holds entities, an entity where it holds literals;
    5. probe: one ASK query per pattern about a named entity, so empl-Heinrich.Hoch a pv:Manager is caught before the query runs empty;
    6. send what is still wrong back to the model, at most twice, while the budget allows. An answer with no rows is sent back once more.
