    Try it

    Step through

    Load a knowledge graph and its ontology, ask a question, and watch Hermes compile it into SPARQL: the model parses it once, and every later phase is symbolic and shown as it happens.

    What runs where

    Everything runs in your browser, and it is the real code. Hermes's Python package (the same wheel the benchmarks run) is installed under Pyodide, and its queries run on Oxigraph compiled to WebAssembly, the engine Hermes uses for local graphs. Only the model is not here: the sample questions replay the replies Llama 3.1 8B gave in the committed CK26 run, and for any other question you use a model you run (Ollama, a small in-browser model, or an endpoint) or paste its replies. For each sample, the page checks that it reaches the same query as the native Python run.

    The phases

    1. Parse. One model call reads the question into a goal (what to return, of which type, one or many) and a plan of SPARQL algebra operators. Words it cannot name in the graph's terms stay in [brackets].
    2. Repair. What small models commonly get wrong is fixed before binding: an IRI the graph does not contain becomes a phrase again, and a value written as a quoted string is bound both as the literal and as the entities it may name.
    3. Bind. Each phrase gets ranked candidates by its position: a property (or its inverse) in predicate position, a class after a or in the goal, an entity or value elsewhere. Candidates come from the ontology's labels and local names and from the terms the data uses.
    4. Check. The best joint assignments become candidate plans, and the verifier types each against the ontology before anything runs. Where the ontology declares no range, the kind of values the data holds (literals or entities) stands in. A name written as a literal is also tried as the entity it names.
    5. Price. Each well-typed plan gets System R estimates from the graph's statistics, rows and C_out, and a logistic estimate p of being right.
    6. Run. The planner runs the plan with the best p net of its price. The result updates p; past the threshold it stops. Otherwise it runs the next one, and when a reading's share of the runs is spent, it asks the model again with what it saw.
    7. Answer. The most probable plan, with p as its confidence. Below the abstain threshold, Hermes says so instead of claiming an answer.

    Your own graph

    Choose Your own ontology and data and load Turtle, N-Triples, RDF/XML, N-Quads or TriG files. The ontology files are read for the vocabulary the model sees (classes, properties, labels, domains and ranges); data and ontology are queried together, as Hermes's benchmark graphs are. With no ontology, the vocabulary is read from the data. Nothing is uploaded: the files stay in the page.

    What to expect

    With Llama 3.1 8B, the budgeted planner scores 0.089 set F1 on the held-out CK26 questions (0.081 for the step-by-step agent, with 7 times fewer model calls), and abstains on most questions: the samples include two where it does. See Leaderboard and the ideas behind each phase.
